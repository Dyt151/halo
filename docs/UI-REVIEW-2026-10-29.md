# Halo 界面审查报告 · 可用性 / 响应式 / 美观度

> 审查日期：2026-10-29
> 审查范围：剪贴板面板 `Panel.tsx`、设置主窗口 `MainWindow.tsx`、历史管理 `HistoryPage.tsx`、卡片 `ClipItem.tsx`、详情 `ClipDetail.tsx`、组件库 `ui.tsx`、虚拟化 `VirtualList.tsx`、设计系统 `index.css` + `tailwind.config.ts`
> 方法：UI 设计全栈专家团三分审（视觉 / 体验 / 前端工程），关键结论均经代码逐条复核

## 总评

| 维度 | 评分 | 一句话 |
|------|------|--------|
| 美观度 | 8 / 10 | 设计系统扎实、强调色克制、动效统一、浅色换肤主体到位 |
| 可用性 | 7 / 10 | 核心心流与四态完善，但键盘/无障碍有两处硬伤 |
| 响应式 | 6 / 10 | 桌面窗口尺寸适应有缺口，窄设置窗下历史页工具栏会被裁切 |

**总基调**：这是一个完成度很高的 macOS 风格桌面应用，设计语言统一、细节（空状态行动指引、输入法组合、撤销栈、危险操作确认）打磨到位。唯一成体系的短板是 **浅色主题的覆盖缺口**——它既是美观问题（L1/L2），也是工程维护风险（手工映射易遗漏），建议作为第一优先级处理。

## 一、美观度（视觉设计）

### 🔴 高

**L1 · 浅色主题强调色对比度失效（真实存在，已复核）**
- 现象：`index.css` 的 `.light` 段只映射了 `.light [class~="text-accent"] { color:#b3741f }`（第 498 行），但**没有任何元素使用裸 `text-accent`**，真正被使用的是 `text-accent-500` / `text-accent-400`。这两个类在浅色下未被重映射，仍是饱和琥珀 `#E8A33D` / `#F0B35A`。
- 影响：落在近白底上对比度仅约 **1.9–2.1:1**，远低于 WCAG AA 的 4.5:1。受影响的可见元素：
  - `MainWindow.tsx:140` 侧边栏选中项图标（`text-accent-500`）
  - `ui.tsx:83` 卡片收藏星标激活态（`CardIconBtn active` → `text-accent-500`）
  - Toast 里可能的强调色操作链接
- 修复：在 `.light` 段补两行——
  ```css
  .light [class~="text-accent-500"] { color: #8a5816; }   /* 或更深的 #b3741f */
  .light [class~="text-accent-400"] { color: #8a5816; }
  ```
  （同时可删除那条已失效的裸 `text-accent` 规则。）

**L2 · 浅色侧边栏分层消失（真实存在，已复核）**
- 现象：侧边栏用 `bg-black/[0.15]`（`MainWindow.tsx:223`），浅色映射把它变成 `rgba(0,0,0,0.035)`（`index.css:526`）——仅 3.5% 黑，在近白窗口上几乎看不出分层。
- 修复：浅色下改用同系浅灰填充，例如在 `.light` 把该值提到 `rgba(0,0,0,0.06)` 或直接套 `bg-group`（`#F2F2F7`）语义。

### 🟠 中

- **图标线宽不统一**：UI 内描边 `strokeWidth` 混用 1.8 / 2.0 / 2.2 / 3.5（NavIcon 1.8、设置图标 2.0、CloseButton 叉号 3.5、卡片操作图标 2.0）。视觉重量不一致，建议统一到 1.8 或 2.0（极小关闭叉号保留 3.5 可接受）。
- **个别字号/圆角越界规范**：代码注释声明字号只用 11/12/13/15/17/20/28 七档，但实际出现 `text-[10px]`（`HistoryPage.tsx` 勾选框对勾、`ClipItem` 部分），10px 在 Retina 上偏小吃力，建议统一到 11px。圆角基本守纪，可顺手核对零星 4px 是否必要。
- **三级文字对比临界**：多处 `text-white/40`、`text-white/45`（时间戳、副标题、来源 App）在深色 `#1E1E1E` 上约 4.1:1，对非大字仅临界过 AA。建议提到 `/50`–`/55`。

### 🟢 低

- **选中态视觉语言不统一**：卡片选中=琥珀描边+淡彩底；菜单项 hover=琥珀实底反白；分段选中=琥珀实底。三种"选中"表达（描边 vs 实底）可统一。
- 强调色纪律总体良好，"只用于主操作/选中/聚焦"基本守住，仅勾选框选中用了 `bg-accent-500`，属合理扩展。

### 值得保留
语义色浅色重映射、类型徽章亮字防消失处理、`prefers-reduced-motion` 全局降级、空状态行动指引、Apple 缓动曲线统一。

## 二、可用性（体验设计）

### 🔴 高

**U1/U2 · 卡片内可交互元素嵌套 + 列表缺 roving tabindex（真实存在，已复核）**
- 现象：`ClipItem.tsx:200` 用 `<article role="button" tabIndex={0}>` 包裹真实 `<button>`（`CardIconBtn` 收藏/复制/删除）。WCAG 4.1.2 禁止在可交互元素内嵌套可交互元素；同时面板/历史页**所有**卡片都是 `tabIndex=0`，Tab 会遍历全部（可达数百），对键盘/屏幕阅读器用户是灾难。
- 修复方向：卡片容器改为 `div` + `role="group"`（不再自身可点击语义），内部操作按钮保留；列表引入 roving tabindex（仅当前选中卡片/容器可 Tab 聚焦，方向键在容器内移动）。

### 🟠 中

**U3 · Segment 方向键副作用（Panel 场景，真实存在）**
- 现象：`ui.tsx` `Segment.onKeyDown` 处理 ←/→/↑/↓ 后**未 `stopPropagation`**，事件冒泡到 `Panel.tsx:190` 的全局 `window` keydown，被 `resolvePanelKey` 解析为卡片导航——结果"在分段控件上按方向键，既切筛选又移动了卡片选中"。
- 修复：`Segment.onKeyDown` 处理方向键后加 `e.stopPropagation()`（一行）。

**U5 · ClipDetail 焦点管理缺失（真实存在，已复核）**
- 现象：`ClipDetail.tsx:52` 虽是 `role="dialog" aria-modal="true"`，但打开时未把焦点移入、未做 Tab 陷阱（焦点会跑回背景卡片）、关闭时未归还焦点到触发元素。
- 修复：打开时 `focus()` 对话框或关闭按钮；捕获 Tab 键循环；关闭时 restore 到来源卡片。

**收藏/删除误触风险**
- 删除与复制之间仅 `w-[6px]` 间隔（`ClipItem.tsx:349`），且删除是高频危险操作。已有确认弹窗兜底，但间距偏紧，建议至少 8–10px 或在非 hover 时弱化删除图标。

### 🟢 低

- 错误态文案区 `max-h-[48px]`（`Panel.tsx:384`）可能截断长错误链；可改为可滚动或两行。
- 三态（加载/空/错误）整体完善，空状态均有下一步动作，保留。

### 值得保留
唤出即聚焦搜索、⌘1~9 回贴、选中高亮、撤销/重做、首启引导、`panelKeys` 状态机纯函数抽象、危险操作二次确认。

## 三、响应式 / 布局（体验设计）

> 说明：这是桌面（Tauri）应用，"响应式"指窗口尺寸变化下的布局自适应，而非移动端断点。

### 🔴 高

**R1 · 历史页/设置窗窄宽裁切（真实存在，已复核）**
- 现象：`HistoryPage.tsx:270` 工具栏是 `SearchField w-[240px]`（固定）+ `Segment`（5 项带计数，固有宽度），父容器无 `min-w-0`/`overflow-x`。在设置窗最小宽（约 420px，侧边栏占 200px）下，内容区仅约 170px，搜索框与分段**溢出窗口被裁切**，类型筛选可能整组不可见。
- 修复：工具栏加 `flex-wrap` 或 `min-w-0`+`overflow-x-auto`；`SearchField` 改 `flex-1 min-w-0`；窄窗下侧边栏可收窄或允许内容横向滚动。

**面板竖向压扁风险（真实存在）**
- 现象：面板 `resizable:false`、宽恒 900（横向），但高度随 `board_height_scale` 变化且**无 minHeight 约束**；该值取低时卡片被竖向压扁（`ClipItem` 固定三段 28/中间/30，中间预览被挤压）。`VirtualStrip` 容器 `h-full` 无最小高。
- 修复：给面板设 minHeight；或给 `board_height_scale` 设下限。

### 🟠 中

- **纵向板型与卡片高错配**：Panel 纵向 `VirtualGrid rowHeight=220`（`Panel.tsx:514`），若窗口较矮，220 行高+工具栏 44+标签行+状态栏 36 易溢出滚动；`minColumnWidth` 在 Panel(168)/历史(200) 依窗口宽度跳变列数，卡片宽随之变化，文本预览断行会"抖动"。
- **横向 VirtualStrip 卡片固定 168px**：面板若未来支持更窄宽度，卡片不会自适应收窄。

### 🟢 低

- 长来源 App 名/标签已用 `truncate` 处理，但卡片头部时间戳 `max-w-[112px]` 在极窄列下与来源名竞争空间，可能挤压预览，可再调权重。
- **RingWindow（Finder 环形盘）**：需人工实测 HUD 在 1440p/4K 与 125%/150% 缩放下是否溢出/可读（本次未读全该文件）。

## 四、工程落地（前端工程 · 代码复核）

### 🟠 中

- **Panel 全局 keydown 监听器随状态高频重建**：`Panel.tsx:298` 的 keydown effect 依赖 `items / selected / hasFilter / numHotkeyEnabled / boardStyle …`，每次 `selected` 或 `items` 变化都 remove+add 整个 `window` keydown 监听。功能无碍但浪费，极端时序下理论上可能漏掉一瞬按键。
  - 建议：把 `resolvePanelKey` 所需状态收进 `ref`，effect 仅挂载一次，从 ref 读最新值。
- **浅色主题 remapping 方案脆弱（维护成本）**：`index.css` 的 `.light` 段用约 60 条 `[class~="..."]` 手工映射逐档 `white/xx → black/xx`。任何 JSX 新用到的 `white/xx` 透明度工具类，若没有对应 light 规则，浅色下就会"白字隐身"——**L1 正是这个机制的漏网**。
  - 建议：迁移到语义化 CSS 变量（已有 `--text-primary` 等），组件层尽量消费 `var()` 而非 `white/xx`，从根上消除遗漏。

### 🟢 低

- 搜索防抖 + 中文 `composing` 处理（`SearchField`）+ 回车兜底 `flushSearch`（`Panel.tsx:245`）逻辑周全；建议确认 250ms 防抖在服务端查询侧也实现。
- 全局 window 级监听 / 定时器 / 动画在 `Panel`/`HistoryPage`/`ClipDetail`/`App` 均有清理，良好。

### 值得保留
虚拟化真正生效（`@tanstack/react-virtual` + `ResizeObserver` 算列数 + `overscan`），大列表不卡；`sanitizeHtml` 白名单防 XSS；`Preview` 的 `useMemo` 化富文本消毒；状态机 `resolvePanelKey` 为纯函数便于测试。

## 五、优先修复顺序（建议）

| # | 项 | 工作量 | 影响 |
|---|----|--------|------|
| 1 | **L1/L2 浅色 accent + 侧边栏 remapping** | 3 行 CSS | 浅色模式可读性硬伤，最快见效 |
| 2 | **R1 历史页工具栏响应式**（min-w-0 / flex-1 / wrap） | 小 | 窄设置窗不再裁切筛选 |
| 3 | **U1/U2 卡片去 button 嵌套 + roving tabindex** | 中 | 键盘/屏幕阅读器可达性根治 |
| 4 | **U3 Segment `stopPropagation`** | 1 行 | 消除筛选/卡片导航冲突 |
| 5 | **U5 ClipDetail 焦点陷阱** | 小 | 对话框无障碍闭环 |
| 6 | **面板 minHeight / board_height_scale 下限** | 小 | 竖向板型不压扁卡片 |
| 7 | 浅色 remapping 迁移到语义变量 | 中 | 根除 L1 类遗漏，长期维护 |

> 注：本报告中"真实存在，已复核"的条目，主理人均已对照源码（含 `index.css` 浅色映射、`ClipItem`/`ClipDetail`/`HistoryPage`/`Panel` 关键行）逐条确认；前端工程维度的补充评审因团队消息通道在会话中被重置而由主理人直接以代码复核完成。
