# Halo · 定位卡

> **用途**：给外部读者（协作者 / 评估者 / 未来的自己）一页纸说清「Halo 是什么、为谁做、和别人有什么不同」。
> **原则**：以代码为准。本文件描述的能力均已在仓库中实现；未实现或未验证的部分统一写在「当前边界」，不混进卖点。

## 一句话

macOS 上把剪贴板变成**可检索、可回贴、可再加工**的本地工具——核心三块功能不联网也能用。

## 为谁做

- **高频复制粘贴的办公 / 研发用户**：一天复制几十次 URL、命令、片段，回头就找不到。
- **在 Finder 里干活的人**：需要「新建文件 / 在终端打开」时不必来回切 App。
- **要转换格式的人**：想把 PNG 变 JPG、把 Markdown 变 HTML，不想开预览窗口，也不想把文件传去在线转换站。

## 核心楔子：环形文件转换

剪贴板管理器这一格已经相当拥挤——Maccy、Paste 都在做「更快的剪贴板」，Raycast 也把剪贴板收进了自己的启动器。

Halo 押的是另一个楔子：**把文件格式转换做进 Finder 的手势里**。
按住 `Option` 拖动文件 → 松手在某个扇区 → 就地转换。不用打开预览、不用上传、不用先去查「这个格式转那个格式该用什么工具」。

这是同类剪贴板工具普遍不做的事，也是 Halo 最难被替代的部分。
（*此段为团队判断，非市场调研结论。若要对外使用，建议补一次竞品实测对照。*）

## 四个能力的关系

| 角色 | 能力 | 为什么在这 |
| --- | --- | --- |
| **地基** | 剪贴板 | 日常高频价值所在，也是最需要长期打磨的核心 |
| **入口** | 右键菜单 | 把能力送进 Finder 与桌面，低成本触达 |
| **楔子** | 环形文件转换 | 差异化所在，别人不做的部分 |
| **延伸** | 状态栏控制中心 | 常驻可见的系统状态总览，与剪贴板共享「菜单栏 / 快捷键」交互语言 |

## 差异点

1. **本地优先**：数据全部在 `~/.halo`；剪贴板、右键菜单、环形转换三块完全离线可用，不上传任何内容。
2. **手势优先的转换**：格式转换绑在 Finder 的拖拽动作上，而不是再开一个需要操作的窗口。
3. **克制的边界**：每块能力都明确「不做什么」。不支持的路径（如文本 → 图片、图片 → OCR）会给出具体原因，而不是假装成功。
4. **可扩展**：模块框架（`module.json` 清单 + 权限白名单 + sidecar / iframe / wasm 运行时）允许第三方贡献剪贴板动作、快捷键与设置项。

## 当前边界（诚实版）

- **仅 macOS**。剪贴板轮询、`⌘V` 注入、Finder 扩展、`CGEventTap` 手势、`core/statusbar/` 原生模块都依赖 macOS 私有 API；仓库里的 `linux/`、`windows/` 只是目录骨架，未实现也未验证。
- **同步 E2EE 已落地，本地敏感加密未落地**。同步链路已用 `argon2` + `chacha20poly1305` 实现端到端加密；但「本地把敏感内容加密入库」尚未实现，选择该策略会降级为脱敏。应用默认敏感策略为**脱敏入库**。
- **状态栏依赖私有框架**。「充到满」通过 PowerUI 私有桥实现，系统升级或加固运行时环境下可能需要重新授权。
- **审查覆盖不均**。剪贴板 / 设置 / 历史 / 卡片做过一次系统级界面审查（`docs/UI-REVIEW-2026-10-29.md`）；**状态栏模块尚未做同等深度的审查**，其设计质量目前没有独立结论。
- **仓库当前为开发态**。本文档对应的工作树尚未作为可复现的发布版本交付。

## 一句话边界

> 这是一个 macOS 专用、离线优先、以 Finder 手势为核心交互的效率工具。
> 它不打算去挤剪贴板管理器赛道的前排，而是先把「在 Finder 里换格式」这件别人不做的事做到位。
