# Halo

macOS 上的剪贴板工具。围绕剪贴板做四件事：

1. **剪贴板**——自动记录你复制过的一切，用快捷键唤出面板，回车贴回去。
2. **右键菜单**——在 Finder 里右键，直接新建文件、打开终端。
3. **环形文件转换**——按住 Option 从文件上拖一下，松手在某个扇区就换格式。
4. **状态栏控制中心**——驻留菜单栏，集中呈现电量、蓝牙、音量、输入法、网络等系统状态，并可一键「充到满」。

技术上是 Tauri 2（Rust 后端 + React 前端），数据全在本机 `~/.halo`。「剪贴板 / 右键 / 环形转换」完全离线可用；「状态栏」会读取系统电量等状态信息（不向外发送）。

---

## 四个功能一览

| 功能 | 解决的问题 | 入口 | 关键实现 |
| --- | --- | --- | --- |
| 剪贴板 | 复制过的东西找不回来 | 全局快捷键唤出悬浮面板 | 轮询 `changeCount` + SQLite/FTS5 + `enigo` 注入 `⌘V` |
| 右键菜单 | 右键菜单里没有「新建文件 / 在终端打开」 | Finder 右键 | Finder Sync 扩展 + 文件队列桥 |
| 环形文件转换 | 只是想换个格式，却要开预览/在线转换 | 在 Finder 里按住 `Option`＋左键拖动文件 | 文件类型 Profile → 预设 → Dijkstra 路由 → 引擎 → 原子落盘 |
| 状态栏控制中心 | 系统状态散落在各处菜单，缺乏一处总览 | 菜单栏图标常驻 | `core/statusbar/` 原生模块（电池 / SMC / 蓝牙 / 音量 / 输入法 / 网络）+ PowerUI 私有桥实现「充到满」 |

---

## 已知限制

在开源发布或评估前，请先了解这几点，避免误判：

1. **端到端加密（同步）已落地，本地敏感加密未落地**。多端同步（WebDAV）的 `chacha20poly1305` + `argon2` 端到端加密**已在 `sync/crypto.rs` 实现并接入同步链路**。但「本地把敏感内容加密入库」（`SensitivityPolicy::Encrypt`）**尚未实现**：选择该策略时会**降级为脱敏**（写成 `[敏感内容已脱敏 <hash 前 8 位>]`），不会按明文保存——但这不等于真加密。另请注意：应用**默认**敏感策略已从「明文标记」改为「脱敏入库」（设置中可改回）。

2. **仅 macOS 可用**。核心能力——`changeCount` 轮询 + `enigo` 注入 `⌘V` 回贴、Finder Sync 扩展右键菜单、`Option`＋拖动的 `CGEventTap` 手势、`core/statusbar/` 原生模块——都依赖 macOS 私有 API。仓库里虽有 `linux/`、`windows/` 的目录骨架，但**并未实现、也未在非 macOS 上验证**。构建与运行的前提是 macOS + Xcode Command Line Tools。

3. **状态栏控制中心默认开启**。它读取系统电量、蓝牙、音量等状态信息；其中「充到满」依赖 PowerUI 私有框架桥，在系统升级或加固运行时环境下可能需要重新授权。若不需要，可在设置中关闭。

## 一、剪贴板

### 1.1 功能

**自动记录**

- 复制文本、富文本（HTML）、图片、文件时自动入库，不需要手动保存。
- 每条记录带来源 App 名称和图标，能看出「这段话是从哪个窗口复制的」。
- 内容完全相同（hash 相同）不会重复堆叠，只把已有那条顶到最前。
- 来源 App 可以加黑名单：密码管理器、银行客户端这类应用复制的内容直接不入库。

**悬浮面板**

- 默认 `Control+C` 唤起/收起，再按一次收起。
- 面板是独立浮动窗口，会盖在其他 App 的浮动窗口之上；点击外部自动收回。
- 唤出即聚焦搜索框，可以直接打字过滤；`↑↓` / `←→` 移动选中，`Enter` 回贴，`Esc` 收起。
- 支持横向卡片流和纵向列表两种排列，以及「跟随光标 / 屏幕中央 / 贴底停靠」三种出现位置。
- 面板里 `⌘1`~`⌘9` 直接回贴第 N 条（**只在面板内生效**，不会抢占其它 App 的 `⌘1`~`⌘9`）。

**卡片与自定义**

- 卡片上直接显示内容预览、来源 App、时间，以及收藏按钮；长内容有「查看全文」入口。
- 默认单击只复制、双击或回车才回贴（可在设置里改成单击直接回贴）——回贴是对外操作，不应该因为手抖就发出去。
- 三个全局快捷键都能自己录：唤起面板、粘贴堆栈顶、快捷回复。注册失败会把原因直接显示在对应输入框下，而不是只写日志。
- 监控可以随时暂停（设置页开关），面板状态栏会显示「监控已暂停」，避免用户以为工具坏了。

**搜索与筛选**

- 全文搜索走 SQLite FTS5，多个关键词是「同时包含」语义。
- 可以按类型（文本 / 富文本 / 图片 / 文件）、收藏、分组标签筛选；类型与收藏的计数来自后端全局统计，不随当前筛选变化。
- 列表用虚拟滚动，几千条记录也不会卡。

**回贴与复制**

- 回车回贴：写回剪贴板并模拟 `⌘V`，焦点会先还给「唤出面板前」的那个 App。
- 没有「辅助功能」权限时自动降级为「仅复制到剪贴板」，并明确告诉用户原因，而不是假装失败。
- 可以设置「粘贴为纯文本」（丢弃 HTML 富文本格式）、「粘贴前去掉文本尾部空白」。
- 粘贴成功后可选播放提示音、自动收起面板。

**剪贴板堆栈**

- 把若干条历史「加入堆栈」，之后按顺序依次粘贴。
- 支持粘贴栈顶、栈底、全部（自顶向底，每条间隔 300ms）。
- 可以锁定堆栈，防止收集过程中被误加新条目。

**快捷回复**

- 常用话术按分组管理，默认 `Control+Shift+R` 唤起独立选择器，搜索后回车直接贴进当前 App。
- 分组和条目支持导入 / 导出 Excel，方便批量维护。

**隐私与容量**

- 敏感内容策略三档：不入库 / 脱敏后入库 / 加密后入库（当前版本加密未落地时会降级为脱敏，不会按明文保存）。
- 容量双上限：默认 2000 条、1GB；另有按天数的保留期限。
- 置顶条目不受容量和期限淘汰；删除支持 `⌘Z` 撤销。

### 1.2 实现方式

**捕获：轮询 `changeCount`**

macOS 没有剪贴板变更通知 API，唯一可靠的路径是轮询 `NSPasteboard.changeCount`（Maccy、Paste 都是这么做的）。`src-tauri/src/core/clipboard/` 里的做法是：

- 用 `objc2` 发原始消息读 `changeCount`（外包一层 `NSAutoreleasePool`，避免后台线程泄漏），默认 500ms 一次，配置最低限制 100ms。
- 计数没变就直接返回，几乎零开销；计数变了才真正读内容。
- 读失败（类型不支持、临时失败）也会提交计数，否则同一个 `changeCount` 会被每轮重复读取、永远空转。
- 读写内容走 `arboard`，读取优先级是 **文本 → HTML → 文件列表 → 图片**。图片放最后是有意的：Finder 里复制图片文件时同时带 `file-url`，这种情况下应该记成「文件」而不是「一张图」。

**图片落盘：内容寻址**

剪贴板图片解码成 RGBA8 后编码为 PNG，存到 `~/.halo/data/files/clip_<sha256 前 16 字节>.png`。文件名只取决于像素内容，所以同一张图永远同一路径，重复复制直接复用、不重复编码，也让「按 hash 去重」对图片成立。

**去重与「自己写的回声」**

- 去重键是 `sha256(JSON(内容))`；图片的路径由内容决定，因此 hash 也只依赖内容。
- 回贴和复制都会写剪贴板，`changeCount` 随之 +1，轮询会把这次自写当成「用户又复制了一条」。解决办法是写之前先登记一个指纹（hash + 时间戳，有效期 3 秒），下一轮读到同样的 hash 就丢掉这一次。登记必须发生在写入之前，否则快速轮询可能抢先抓走回声。
- 指纹只吃一次：3 秒内用户真的又复制了同一段文本，第二次会正常入库。

**存储与检索**

- SQLite（rusqlite，bundled + FTS5），单文件 `~/.halo/data/halo.db`。
- 内容以 JSON 存在 `content` 列，`clips_fts` 通过 `rowid` 关联；查询时每个关键词用双引号包裹再拼接，天然是隐式 AND，也避免了 FTS5 特殊字符注入。
- 容量策略在每次入库后执行：先按 TTL 删未置顶的过期条目，再按条数裁掉超出部分，最后循环删除最旧的未置顶条目直到总字节数达标。`max_items` / `max_bytes` 为 0 时回落到出厂默认值——否则一次坏的配置写入会把历史清空。
- 删除图片条目时**故意不删文件**，这样 `⌘Z` 恢复的记录不会指向一个已经不存在的路径；无主 PNG 在启动时统一回收（`prune_orphan_images`）。
- 启动时还会做两件自愈：修复旧版本写坏的非法 JSON 内容、为 `size_bytes=0` 的历史重算体积。

**回贴**

1. 唤出面板时记录当前前台 App 的 pid（如果前台就是 Halo 自己则保留旧值，避免把「上一个真实目标」冲掉）。
2. 回贴时先把内容写进剪贴板，写入前登记自写指纹。
3. 激活记录下来的前台 App，等待约 60ms 让它真正拿到焦点。
4. 用 `enigo` 注入 `⌘V`。修饰键一定会在 `v` 之后松开——否则目标 App 会以为 `⌘` 一直被按着，之后所有快捷键都变成组合键。
5. 任一步失败都不会报「回贴失败」：内容已经在剪贴板里了，降级为「仅复制」，并说明原因。
6. 「最近使用时间」更新失败只写日志，不影响这次回贴的成功判定。

**面板窗口**

- 面板是 `alwaysOnTop` 的无边框透明窗口，默认 900×220，最大宽度 1180。
- macOS 侧把 `NSVisualEffectView` 垫在 webview 之下做真实毛玻璃（面板用 HUD 材质、设置窗口用侧边栏材质），圆角也交给这层视图，窗口阴影才不会露出直角。
- 窗口层级被抬到 25（`NSStatusWindowLevel`），避免同屏装了别的剪贴板工具时被对方压住。
- 失焦收起带 400ms 宽限，防止「刚显示就被自己的焦点事件收掉」。
- 面板一出现就异步补一次剪贴板轮询：用户经常「复制完立刻按快捷键」，常规 500ms 轮询可能还没轮到，不补这一下会看到旧列表。
- 面板是 hide 而不是销毁，所以「出现动画 / 复位滚动 / 清空搜索词」由前端监听 `halo://panel-shown` 重放；原生 `focus` 事件作为兜底（webview 未就绪时事件会丢）。

**入库流水线**（`src-tauri/src/state.rs`）

`监控事件 → 监控开关 → 来源 App 黑名单 → 敏感内容策略 → hash → 导出来源图标 → 写库 → 发事件（前端与模块总线）`。

敏感识别规则是启发式的：只看 400 字节以内的短文本（代码、长段落基本不会被误判），匹配已知密钥前缀（JWT、`ghp_`、`xoxb-`、`AKIA`、`sk-`、PEM 私钥、`ssh-` 等）和 `password=…` / `token=…` 这类键值对。脱敏结果写成 `[敏感内容已脱敏 <hash 前 8 位>]`——不能所有敏感内容都写同一个占位串，否则按 hash 去重后连着复制的两个密码只会剩一条。

## 二、右键菜单

右键菜单在两个地方出现，共用一套动作执行层。

### 2.1 Finder 里的右键菜单（文件 / 文件夹）

装好 Finder 扩展后，右键菜单里会直接出现 Halo 的动作，不需要展开「服务」子菜单：

| 菜单项 | 行为 |
| --- | --- |
| 新建文本文件 (.txt) | 在当前目录创建空 `.txt` 并用 TextEdit 打开 |
| 新建 Markdown 文件 (.md) | 同上，`.md` |
| 在终端中打开 | 新开 Terminal 窗口并 `cd` 到目标目录 |

Word / Excel / PowerPoint 不重复提供：装了 WPS 的机器上，原生菜单里的「使用 WPS 新建」已经覆盖这三种文件，菜单里再放一份只会变长。

> 环形转换不占右键菜单：它的唯一入口是「Option＋拖动」（见第三节）。

目标目录的判定：选中文件夹时以该文件夹为目标，选中文件时以它所在文件夹为目标。

> 桌面空白处的右键保持系统原生，Halo 不接管。

### 2.2 历史条目右键菜单（应用内）

在剪贴板面板或历史页里右键任意一条记录：

- 回贴 / 复制 / 加入堆栈
- 置顶 / 收藏
- 标签子菜单：选已有标签、新建标签、从标签移除
- 已安装模块贡献的动作（悬停会显示是哪个模块提供的）
- 删除

菜单是前端自绘的，会按屏幕边缘自动翻转位置；标签子菜单在贴近右缘时改为向左展开。

### 2.3 实现方式

**Finder 扩展只出菜单，不干活**

Finder Sync 扩展是独立进程，不能直接调用 Rust。所以它做两件事：往右键菜单里放条目、把用户点的动作写成一个 JSON 请求文件。

- 菜单只在「选中项目」和「容器（空白处）」两种上下文里出现。
- 监视范围是显式的几个实体目录：真实主目录、桌面、外接卷（`/Volumes`）、`/Users/Shared`、`/private/tmp`、`/private/var/tmp`、`/opt`。系统目录（如 `/usr`）不在名单里，不会出现 Halo 菜单。
- `/Applications` 放进 `directoryURLs` 也不会生效——Finder 在那里从不调用扩展，这是系统限制，不是漏配。
- 请求写成 `{action, paths, container, created_at}`，先写临时文件再 `rename`，保证主程序不会读到半个 JSON。
- 队列目录三级回退：App Group 容器（`group.com.halo.desktop`）→ 扩展自己的容器 → `Application Support/HaloFinder/Requests`。写完再发 `halo-finder://wake` 尝试立即唤醒。

**主程序侧：250ms 轮询 + 严格校验**（`src-tauri/src/core/services/bridge.rs`）

- 每 250ms 扫一次队列目录，按文件名里的毫秒时间戳排序，保证点击顺序不乱。
- 超过 10 分钟的请求直接丢弃（App 没运行时的堆积不该在下次启动时突然执行）。
- 坏 JSON 不改不删，改名成 `.json.bad` 保留现场，方便排查。
- 只接受绝对路径，并且要求路径当前存在——扩展传来的东西一律当不可信输入。
- 动作字符串与 Rust 侧 `ServiceAction::message()` 严格一一对应，两边改名就会失配。
- 扩展的启用/停用通过 `pluginkit` 完成（macOS 15 起系统设置里已没有 Finder 扩展开关），设置页的开关直接联动扩展启停。

**动作执行层**（`src-tauri/src/core/services/macos.rs`）

- 新建文件先 `create_new(true)` 占位，重名自动加序号——这样既不会覆盖已有文件，也避免了「先判断再创建」之间的竞态（TOCTOU）。
- 「在终端中打开」用 AppleScript 实现，路径里的引号和反斜杠会先转义，避免路径变成脚本注入。

## 三、环形文件转换

### 3.1 功能

**唯一入口：Option＋左键拖动**

在 Finder 里按住 `Option` 把文件拖出去，超过 8px 就在起手点铺开圆环；把文件推到某个扇区上松手即转换。

- 没有全局快捷键，也没有 Finder 右键服务：这两个入口已经下线，避免同一件事有三套操作。
- 盘上的选中项以**起手文件**为权威：用户拖的是哪个图标，就转哪个文件；如果它本来就在多选里，则整批一起转。
- 松手在中心、环外或从未移出起手点：取消，不启动任何任务。

**环形盘交互**

- 只有一面：没有正/背面，没有 `Tab`、滚轮、单击、`Enter`、方向键、`Esc`。运行态只认一次拖动。
- 每个扇区就是一个转换预设，最多 12 个；扇区上直接写「会转几个、跳过几个」。
- **不可用的扇区留在原位**，只降低不透明度；hover 时中心显示原因（例如「这批文件里没有能用到它的输入」），松手在上面不执行，停留 1.3 秒把原因说完再收起。位置不变才能保证「设置里看到的位置」与「运行时落点」一致。
- 中心显示本次选中的 Profile 名（图片 / 文本 / 其他文件）和文件数。
- 上一次用过的动作会预高亮，但**不会自动执行**。
- 转换时就地显示进度环；超过 5 秒没结束，界面交接给系统通知，不占着屏幕。
- 结束给出汇总：转换 / 跳过 / 失败 / 取消各几个，外加「不保真」警告（例如动画 GIF 只保留首帧、透明通道被合成到背景色）。
- 转换中或窗口失焦都算取消；取消会回滚还没写完的输出，已经完成的文件保留。

**转换能力**

图片之间可以互转，文本之间可以互转，图片可以「包」成文档；反过来不成立：

| 源 | 可转目标 | 说明 |
| --- | --- | --- |
| PNG / JPG / WebP / GIF / BMP / TIFF | 其余 5 种图片 | 图片引擎内部编解码，同格式重编码需要预设显式开启 |
| PNG / JPG / WebP / GIF | Markdown、HTML | 生成引用图片的文档；HTML 用内嵌（base64）方式 |
| BMP / TIFF | Markdown | 可以引用，但不内嵌进 HTML |
| Markdown / HTML / TXT | 另外两种文本 | 三方互转 |
| 图片 | 同格式（重新编码） | 只有 `reencode_same_format` 预设会这么做，例如 JPG 85% → JPG 70% |

**故意不支持的两条路**：文本 → 图片（需要排版渲染）、图片 → TXT（需要 OCR）。它们在图上是不可达的，会给出明确原因，而不是假装成功。

**三层模型：预设 / Profile / 扇区**

- **预设**（Preset）回答「怎么转」：目标格式、质量、输出目录与重名策略；两个「JPG」可以是 85% 和 70% 两条独立预设。
- **Profile** 回答「什么文件用哪些预设」：一套扩展名 + 一条 `preset_ids` 顺序。默认三个：图片（png/jpg/webp/…）、文本（md/html/txt）、其他文件（兜底，扩展名为空 = 所有未匹配类型）。
- **扇区**（RingSlice）是运行时那一批文件下每个位置的可用性与原因。

选盘规则（顺序即优先级）：

1. 第一个「包含本批全部扩展名」的普通 Profile；
2. 第一个「扩展名非空且包含全部」的混合兜底；
3. 第一个扩展名为空的混合兜底（catch-all）；
4. 其余情况取第一个混合兜底，再不行取第一个 Profile。

普通 Profile 优先于兜底，所以「png + jpg 混选」会落在图片盘；同族扩展名可以写在同一个 Profile 里。至少保留一个混合兜底，没配过的类型也有盘可拖。

**在设置里编辑 Profile**

「设置 → 环形转换」分四块：手势与权限、文件类型 Profile（新建 / 命名 / 排序 / 扩展名）、当前 Profile 的圆环（拖入 / 排序 / 移除）、可用预设与预设编辑器。每次成功编辑立即保存，没有「应用」按钮。扩展名支持 `png, jpg`, `.webp` 这类手写形式，规则与后端完全一致（trim、小写、去前导 `*`/`.`、最长 16、拒绝非法字符），非法项当场提示而不是默默吞掉。

### 3.2 实现方式

**预设是动作的身份，不是格式**（`src-tauri/src/core/convert/preset.rs`）

两个「JPG」可以同时存在（85% 和 70%），它们是两条独立预设、两个独立扇区，互不影响。预设结构：

```
target      目标格式，或 "*" 表示与源格式相同（重编码）
image       JPEG 质量（默认 85）、透明合成背景色（默认 #FFFFFF）
output      输出目录、重名策略（Rename / Overwrite / Skip）、
            命名模板（默认 {name}.{ext}）、only_if_smaller
```

内置预设有 10 条：9 种格式各一条，外加 `img.jpg.q70`（JPG 70% 重编码）。旧配置的「正面 + 背面」顺序会在迁移时合并去重（最多 12 条），再按预设类别拆成图片 / 文本 / 其他文件三张盘，用户原来的偏好顺序不会被打乱。

**读取 Finder 选中项**（`src-tauri/src/core/finder/mod.rs`）

用 AppleScript 向 Finder 要 `selection`，路径之间用 `0x1F` 分隔（文件名可以含换行，不能用换行当分隔符）。空选中、前台不是 Finder、无自动化权限、超时、失败、不支持各有独立状态和中文提示，不会笼统报「失败」。

**Option+拖动：为什么不用热键**（`src-tauri/src/core/option_tap/mod.rs`）

系统热键 API 只接受「修饰键 + 主键」，`Option+拖动` 不是热键，只能靠 `CGEventTap` 旁观鼠标事件。判定策略是「宁可漏触发，也不误触发」：

- 起手时 `Option` 必须已经按下；拖到一半再按不接管（那时 Finder 已经在拖文件，吞事件会让它的拖拽会话卡住）。
- 位移超过 8px 才接管，`Option+单击` 不弹盘。
- 只在 Finder 前台、且环形盘没在屏上时接管。
- 按下 `Option` 的那一刻就先异步读一次选中项（有效期 5 秒）：如果等到拖动开始再读，会卡在 Finder 的 `mouseDown` 追踪循环里，实测能阻塞近 5 秒。
- 接管后吞掉后续 `leftMouseDragged`，Finder 不会启动真正的文件拖拽；松手事件照常放行，Finder 把它当一次单击。
- 起手文件是载荷的**权威**：按下左键的瞬间同步做一次 AX 命中（`AXUIElementCopyElementAtPosition` + 上溯 `AXURL`），拿到的就是手指下那个文件。它不在预取的多选里就只转它自己，在多选里就整批一起转。
- **松手时不核对选中项**：拖动接管后 Finder 只看到单击，选中已经被收缩，再去「复核」只会得到错误结论。先前的「再拖一次」提示因此删除了。
- AX 未命中（不在图标上 / 无权限）才退回预取选中项——宁可少转也不转错。

**权限自检：为什么「按了没反应」要能自己说清楚**

`CGEventTap` 必须有「辅助功能」授权才建得出来，而开发构建用的是 ad-hoc 签名——每重新构建一次，二进制指纹就变一次，系统里那条旧授权记录会**看起来仍勾着、实际已失效**。这时用户按 Option 永远没反应，日志却只有一行 `accessibility=false`。

所以手势层把自己拆成了可观测的四段：`enabled`（开关）、`accessibility`（系统授权）、`tap_alive`（事件监听是否真的建起来）、`frontmost_ok` + `last_note`（现场条件与最近一次失败原因）。设置页每 1.5 秒轮询一次，窗口一获焦点立刻刷新，授权勾上后 3 秒内自动接管、不用重启；「修复授权」按钮会先 `tccutil reset` 清掉失效记录，再带系统提示重新登记。

**状态机与会话失效**（`src-tauri/src/core/ring/mod.rs`）

状态只剩单手势能走到的六种：`idle / capturing / probing / ready / empty / converting`。失败与空不再分门别类枚举，而是同一张提示盘带不同原因（`hint`）。会话有一个单调递增的 `generation`，新会话一开会把旧盘的所有回调和事件作废，避免上一个盘的结果画到新盘上。

**路由：Dijkstra，最多 3 步**（`src-tauri/src/core/convert/router.rs`）

- 能力来自引擎声明的边，不是写死的转换矩阵。
- 普通路由 `MAX_STEPS = 3`，中间产物不进最终输出。
- 源格式 == 目标格式时**只认显式 self edge**：既不默认复制，也不默认报错。
- 同代价时按固定格式顺序取路径，保证同一对格式每次选出的路线一致（用户看到的「TIFF → PNG → HTML」不会时好时坏）。
- 规划失败分三种原因并各自给出中文说明：本就是同格式、图上不可达（需要 OCR / 排版引擎）、步数超限。

**引擎**（`src-tauri/src/core/convert/engines/`）

| 引擎 | 声明的边 | 单步成本 | 并发上限 |
| --- | --- | --- | --- |
| image | 6 种图片全连接（含同格式重编码） | 10（同格式 12） | 2（大图解码吃内存） |
| text | md / html / txt 六向 | 5 | 4 |
| document | 6 种图片 → md；PNG/JPG/WebP/GIF → html | 20（终结边） | 2 |

图片引擎会保留 GIF 的动画（同格式重编码时逐帧处理）；目标格式不支持透明时按预设背景色合成并写进警告；文档引擎把图片以引用或 base64 内嵌的方式包进 Markdown / HTML。

**任务与并发**（`src-tauri/src/core/convert/job.rs`）

- 一个任务一次只跑一个预设，文件级最多 4 个 worker，每个引擎再受自己的并发上限约束——三层限流，避免 50 张大图同时解码把内存打爆。
- 每个文件都有明确结果：`converted / skipped / failed / cancelled`，跳过也带原因（已是目标格式 / 无路由 / 格式不认识），不存在静默丢文件。
- 取消通过 `CancelToken` 传递；已经开始写盘的文件会回滚，不会留下半个输出。

**输出：先预留，再原子提交**（`src-tauri/src/core/convert/output.rs`）

1. 确保输出目录存在，顺手清理 1 小时前的残留临时文件。
2. **源文件保护优先**：目标路径和源文件是同一个文件时直接拒绝，这一条优先于任何「覆盖」策略——否则「转成 JPG」会把自己的源文件写坏。
3. 按预设的重名策略决定最终文件名（自动加序号 / 覆盖 / 跳过）。
4. 在锁内一次性完成「检查 + 占用」，避免两个 worker 同时选中同一个名字。
5. 先写 `.名字.halo-<uuid>.tmp`，全部成功后再 `rename` 到目标名。失败或取消只删临时文件，目标位置永远不会出现半成品。

**结果反馈**

转换结束后按类别记住这次用的预设（只用于下次预高亮），并汇总成一句话通知：「完成 N · 跳过 N · 失败 N」，取消时额外标注「已取消」。成功时可以在 Finder 中显示输出文件。

## 四、权限与数据

| 能力 | 需要什么 | 没有时的表现 |
| --- | --- | --- |
| 回贴（自动 `⌘V`） | 系统设置 → 隐私与安全性 → 辅助功能 | 降级为「仅复制到剪贴板」，并提示原因 |

数据全部在 `~/.halo/`：

```
data/halo.db      SQLite 主库（历史、配置、快捷回复、模块清单）
data/files/           剪贴板图片（内容寻址 PNG）
icons/                来源 App 图标缓存
modules/              已安装模块
logs/                 运行日志
```

应用是单实例的：第二次启动只会把已有实例的窗口拉到前台，不会出现两个进程同时监控剪贴板、同时写数据库。

## 五、其它能力

三个核心功能之外，还有几块支撑设施：

- **模块框架**：`module.json` 清单 + 权限白名单 + sidecar / iframe 运行时 + 贡献点（剪贴板动作、快捷键、设置页、命令），`modules.example/filee/` 是最小示例模块。
- **多端同步**：WebDAV provider，可选 `chacha20poly1305` + `argon2` 端到端加密，本地优先。
- **设置中心**：通用、剪贴板、环形转换、右键菜单、同步、权限、关于；主窗口打开时停在上次的分区。
- **高级历史管理**：从面板或「剪贴板」设置进入的二级页，做批量浏览、筛选、标签与容量清理。
- **原生菜单栏**：`⌘,` 打开设置、`⌘Q` 退出；「窗口」菜单里能直接打开面板、历史、设置。关闭窗口只是隐藏，不会退出进程。
- **状态栏「VPN」二级页**：识别本机在跑的 FlClash / Clash 核心——配置里的混合端口 + 回环 REST 控制口，读出接管状态、模式、策略组、节点与实时网速，可以在面板里切「规则 / 全局 / 直连」、选节点、批量测延迟。「流量接管」只改 macOS 系统代理那三项（`networksetup`，写完回读校验、不符立刻回滚），不碰订阅、不改 FlClash 的配置、菜单栏提示直接说「代理已接管」；判定只看系统代理实际指向的那个端口——核心退出、或核心换了端口而系统代理还指着旧端口，都改报「代理已失效（去面板关掉）」，面板保留关闭入口。FlClash 没开外部控制时只给接管开关和端口读数。

npm install
npm run tauri dev      # 开发模式
npm run tauri build    # 打包 Halo.app

Finder 右键菜单只能在**打包后的 App** 里验证（`tauri dev` 的裸二进制里没有扩展）。
